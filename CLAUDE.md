- Call peers with explicit models: `codex exec -m gpt-6-astra -c model_reasoning_effort=high`, `agy --model gemini-3.8-flash-high`.
- Hard gate (user, 10/8, after repeated misses): no plan, design, prompt or test plan goes to dev until GPT, Gemini and the Sonnet critic have answered on it. Build exactly the user's spec: add no scenarios of your own, and do not restate a user rule with an exception. Check the user's earlier instructions before changing a feature. Test every feature in a normal show flow before tuning.
- At every plan, test, result and logic review, write the judge's view: what an AI Builder Cup judge would criticize and what change raises the score.
- The goal is a general platform: 100% on any unseen product. No product-specific prompts, few-shots, heuristics or rule carve-outs; products enter only via onboarding; pass/fail on a sealed pool of other products.
- Manual steps are design flaws: never ask a customer to match a template; absorb any document format; humans only approve.
- If our logic misses its pass lines after a small patch budget (1-2 rounds), scrap it and rebuild; set kill criteria before testing.
- Git commit messages (header / body / footer, separated by blank lines):
  - Header (required): `type(scope): subject`; scope is optional. Types: feat, fix, build, chore, ci, docs, style, refactor, test, perf.
  - Subject: 50 characters or fewer, imperative (not past tense), no trailing period, capitalized first letter for English.
  - Body (optional, only when the header is not enough): wrap at 72 characters, say what changed and why, not how.
  - Footer (optional): references such as `resolves: #1137` or `Issues #1234`.
  - Keep the attribution line the harness asks for as the last footer line.
- Decks and explainer HTML go in `docs/decks/` (build scripts in `docs/decks/build/`).
- Scope (user, 10/6, restated 10/7): this team (the user, the planning session and dev) works only on the STT-driven live path: speech-to-text, the judges on its text, alert display and latency, plus UI/UX work on any screen (user, 10/7: "UI/UX는 괜찮어"). Viewer comments (classification, answers, posting) and pre-broadcast tasks (onboarding, approval, brief) belong to other people: do not change their code, prompts or settings, and do not measure or tune them. A change that would touch them goes to the user first.

## Quirks

- STT chirp_3 works only in region `us` (403 in Asia). Gemini 3.5 Flash-Lite and 3.8 Flash work only on the global endpoint.
- Cloud Run runs max-instances 1. From D-369 the deploy script sets `STORE=firestore` (database `live-studio`, created 10/9 in ai-budiler-cup-uh-team-pjt, us-central1). Show data (sessions, transcripts, alerts, events, segments, agent calls) is written there; revision 00007 still ran `STORE=memory` because it was deployed before D-369.
- Gemini 3 context caching needs a prefix of 4,096 tokens or more. Only the fact checker benefits today.
- Korean output from Python on this Windows machine needs `PYTHONIOENCODING=utf-8`.
- agy on this PC (10/10) cannot use tools: its `googlecloudtools.datacloud_telemetry` pre-tool hook fails (a quoted path), so any agy task that must read a file or an image fails. Text-only `agy -p` answers still work. For Gemini on files, call Vertex `gemini-3.8-flash` (thinking HIGH, `max_output_tokens` 65000: HIGH thinking alone used 29-39k tokens) through the backend's `google.genai` client. Do not edit the agy config.
- The submission deck (`docs/decks/build/build_submission_1011.py`) reads the organizer template `Submission Template _ AI Builder Cup.pptx` from the repo root (not in git; do not commit it). The template font is Google Sans Flex, which ships only as a variable font (google/fonts `ofl/googlesansflex`); PowerPoint needs static faces named "Google Sans Flex", "... Medium", "... SemiBold" installed (cut with fontTools instancer, installed per user on 10/11). Saving through PowerPoint with embedded fonts keeps it right on other PCs.
- Writing eval or corpus task text through bash `python -c "..."` or an unquoted heredoc expands `$80` to empty ("S$80" became "S0" in sealed pool 3). Use the Write tool or `<<'EOF'`.
- PowerShell flattens `@(@("a","b"))` into one list, so a one-element list of arrays loops over strings. Write `@(,@("a","b"))`.
- Eval scorers must treat zero-decimal currencies (KRW, JPY, VND, IDR) as whole units; the app already does (D-243).
- Vertex AI Search defaults drop low-relevance hits ("It cures eczema" returned nothing). Use `relevanceThreshold: LOWEST`, `pageSize` 5-10 and the market filter.
- Code may overrule a model verdict, but never silently: look for "fact claim dropped by code" and "compliance violation dropped by code" in the logs. `eval_adversarial` rows carry `dropped: [{reason, ...}]`. A right model answer with no alert is almost always one of these drops (D-248, D-250, D-260).
- `FACT_MODE=docs` (FD, default) reads a release's original files from `<ONBOARDING_DIR>/<job_id>/files.json`. A release without stored files behaves as `record`. Record fields added after a release was made (pack counts, offer conditions, target group) appear only after re-onboarding.
- In the cloud, onboarding state lives in `gs://ai-budiler-cup-uh-team-pjt-live-studio-onboarding/onboarding/` (D-263; bucket name since the 10/6 project move). The bucket is the source of truth; the container's ONBOARDING_DIR is only a cache that is refilled at start. Never edit the bucket by hand: releases and packs are write-once.
- Approving a release also runs the BriefAgent (about 30 s, D-265) and writes `briefs/<release_id>.json` (write-once). A release approved before D-265 has no brief: its show keeps the approved claims as points and only brand, product and ingredient names as STT hints until it is approved again.

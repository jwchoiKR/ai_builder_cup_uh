# 공개 대회 레포 재채점 (10/6)

지난 비교(`ai-builder-cup-repos.html`, 10/5)를 서비스 내용만으로 다시 매겼다. 배포 링크, 영상, 소개 글의 꾸밈은 점수에서 뺐다.

## 요약

- 서비스 내용만 보면 우리는 공개 레포 약 50개 중 **3등**(8.40점)이다. 채점 오차를 생각하면 2~5등 사이로 본다.
- 우리보다 위는 Gapline(8.70, 화면 해설)과 Taal(8.45, 리테일)이다. 리테일·커머스 분야에서는 Taal이 근소하게 앞선다.
- 지난 덱 기준으로 다시 계산한 우리 점수는 7.65점이었다. 자동 제품 등록, 규정 팩, 처음 보는 제품 시험, 주입 공격 시험이 점수를 올렸다.
- 우리가 가장 앞서는 것은 시험의 깊이와 3초 안의 실시간 음성 판정이다. 가장 뒤지는 것은 확장(메모리 저장, 서버 1대), 비용 숫자, 처음 보는 제품에서 합격선 미달이다.
- 대회 제출 마감이 10/18이라 다른 팀도 계속 만들고 있다. 이 점수는 10/6 기준 사진이다.

## 0. 어떻게 매겼나

- **자료:** 레포 소개 글 요약 146개(10/5 20:12 목록 `_index.json`, 10/5 03:04 목록 `_cup.json`)와 GitHub 커밋 기록(10/6 조회). 상위 레포 몇 개는 커밋 메시지로 10/4 이후 새 코드를 확인했다.
- **대상:** AI Builder Cup 2026 참가작만 남겼다. 다른 대회(Ramp, Agent Builders Cup, 월드컵 앱 등)와 프로필·목록 레포는 뺐다. 지난 덱 5등이던 CycloneShield는 소개 글에 다른 대회("Build with AI: Code for Communities")라고 적혀 있어 이번에 뺐다.
- **기준(공식 배점):** 기술 40(의미 있고, 실제로 돌고, 확장되는 Google Cloud AI 사용), 문제 25, 혁신 25, UX 10. 항목마다 10점 만점으로 매기고 `기술×0.4 + 문제×0.25 + 혁신×0.25 + UX×0.1`로 합쳤다.
- **기술 점수에서 본 것:** AI가 실제로 무엇을 판단하는지, 코드가 무엇을 막는지, 시험 규모(몇 건을 몇 번), 처음 보는 데이터로 시험했는지, 저장과 확장 구조.
- **빼고 본 것:** 바로 써 볼 링크, 영상, 발표 자료, 소개 글의 배지와 꾸밈.
- **한계:** 다른 팀은 소개 글과 커밋 기록만 봤고 코드를 돌려 보지 않았다. 우리 것은 코드와 시험 결과를 다 안다. 그래서 우리 약점은 더 잘 보이고, 다른 팀 약점은 덜 보일 수 있다. 이번 채점은 Claude 혼자 했고 GPT·Gemini 교차 검토는 하지 않았다.

**우리가 다른 팀보다 앞서는 점 (근거 있는 것만)**
- 시험 규모와 방식: 봉인 세트를 라운드마다 새로 만들고, 정답은 다른 모델이 정답을 모른 채 따로 붙이고, 각 3회 돌린다. 합격선은 결과를 보기 전에 고정했다. 다른 상위 팀의 시험은 6~25건, 1회가 많다(Gapline 6개 영상, ContextBridge 25건, Groundtruth 18문항, ReadiCheck 6건).
- 실시간: 말이 끝나고 화면 경고까지 p95 2.18초(위험 문장 150번), 2.59초(사실 오류 150번), 클라우드 측정.
- 문서 형식을 가리지 않는 등록: TrueLedger·Kaigo·ARTHA도 문서를 읽지만 정해진 종류(은행 명세서, 자격증)다. 우리는 형식과 언어를 가리지 않고 숫자를 글자로 쓴 문서까지 받는다.

## 4. 점수를 가장 올릴 변경 (심사위원 시점)

효과 숫자는 이 채점 방식으로 본 추정이다.

1. **처음 보는 제품에서 합격선을 넘긴다.** 사실 확인 오경고 5% 이하(지금 5.6~7.4%), 식품 규정 팩(HSA·MOH 원문, 이미 계획됨)으로 P4 재시험, 등록 안전 항목 개선. "범용 플랫폼"이라는 주장의 근거가 이것 하나다. 기술 +0.3~0.5, 혁신 +0.2 추정. 개발 세션에 보낸 L1~L7 수정 뒤 1~2회 안에 안 넘으면 사실 확인 방식을 다시 만든다(중단 기준을 시험 전에 적어 둔다).
2. **저장과 확장, 비용을 숫자로 만든다.** 방송 상태를 Firestore에 두고 서버가 다시 켜져도 이어지게 한다. 서버 2대 이상에서 한 방송이 깨지지 않는지 잰다. `LLM_USAGE_REPORT`로 합성 방송 12분을 돌려 방송 1시간 비용을 실측한다. 기술 점수의 "확장" 부분이 지금 가장 비어 있다. 기술 +0.3 추정.
3. **"Gemini만" 비교표를 만든다.** 봉인 세트에서 (가) 제품 문서와 규정을 다 넣은 한 번 호출, (나) 후보 D·E, (다) 지금 구조 A를 같은 표로 놓는다. 잘못 게시, 탐지, 오경고, 지연을 나란히 둔다. 이미 있는 후보를 다시 쓰므로 비용이 적다. 기술 +0.2 추정.
4. **시험 운전을 심사위원 실험실로 넓힌다.** 심사위원이 자기 제품 문서를 올리면 자동 등록 → 승인 한 번 → 등록 기록에서 위험 문장과 안전 문장을 자동으로 만들어 → 판정 결과와 맞힌 비율을 보여 준다. HANDOFF 7장 0번(시험 문장 자동 생성)과 같은 일이다. 1번이 먼저 통과해야 의미가 있다. 혁신 +0.2, UX +0.3 추정.
5. **사람 진행자 방송 1회를 시험으로 남긴다.** 팀원 녹음으로 경고 시간, 놓친 것, 진행자가 경고를 읽었는지를 기록하고, 그 녹음을 재생 시험으로 바꾼다. UX와 문제 점수의 "초보 진행자를 돕는다" 주장을 받쳐 준다. UX +0.3, 문제 +0.1 추정.

2번은 1번과 따로 진행할 수 있다. 3번은 비용이 가장 적다. 이 다섯 개를 다 하면 합계가 8.40에서 약 8.8~8.9로 오른다고 본다(추정). Gapline 수준이다.

**하지 않아도 되는 것:** ADK를 판정 경로에 억지로 넣는 일. 지연 측정이 직접 병렬 호출을 고른 근거라서, 그 측정을 보여 주는 편이 낫다. ADK를 넓히고 싶다면 지연이 상관없는 등록 단계를 ADK 작업 흐름 후보로 만들어 같은 시험으로 비교한다.

## 5. 이 채점의 한계

- 다른 팀은 소개 글 기준이다. 소개 글에 없는 시험 결과가 있을 수 있다(Provenance는 평가 화면이 있다고만 적었다).
- 10/18 마감까지 다른 팀도 바뀐다. 특히 IntentGuard(설계가 좋고 아직 비어 있음), Provenance, Kavach, Second Thought는 오를 수 있다.
- Finwings와 Factory Time Machine은 10/6에 레포가 열리지 않았다. 비공개로 바꾼 것으로 보이며, 심사 때 공개될지는 모른다.
- 비공개로 참가한 팀은 이 목록에 없다. 이 등수로 결선 확률을 말할 수 없다.
- shxunxk/Google-AI-Builders-Cup-2026, Hitmantejas/AIBuilderCup-Valtech는 소개 글이 없거나 레포가 비어 있어 채점하지 못했다.

## 교차 검토 (codex gpt-6-astra high, 10/6 4시)

- 상위 10개 목록은 그럴듯하지만, 0.5점 차이로 순위를 가르는 것은 근거가 약하다(요약만 보고 매긴 점수).
- Gapline 1위는 맞지만 점수는 후하다(8.2~8.5 권장). Taal은 실제 Gemini 실행 근거가 한 시나리오 5회뿐이라 높다(7.8~8.2 권장). SentinelGraph(시간 분할 AUC 0.914 vs 0.866)와 Kaigo는 낮게 매겨졌다. Groundtruth는 ReadiCheck보다 위가 맞다.
- **우리 점수 8.4는 지금 후보 기준으로 높다. codex는 7.9를 준다**(기술 30/40, 문제 20/25, 혁신 21.5/25, UX 7.5/10). 대표 숫자인 처음 보는 제품 2차 세트가 72.5%이고, 1차 세트 93.8%와 21%p 차이가 나서 일반화를 주장하기 어렵다. 3위는 증명되지 않았다.
- codex가 꼽은 점수 올릴 일: (1) 카테고리·제한·버전·조건 계산을 고치고 새 봉인 세트로 확인, (2) 사람 진행자 비교 시험(정정 성공, 개입 시간, 시간당 경고), (3) 저장소와 재시작·동시 실행 증명, (4) 같은 처음 보는 입력으로 구조 비교, 방송 1시간 비용·지연 실측.
- 이 문서의 8.4는 codex 검토 반영 전 숫자다. 3차 후보 결과가 나오면 다시 매긴다.
